* Python 3.8+
* Установленные в системе консольные утилиты: `fastqc`, `minimap2`, `samtools`, `freebayes`.

### Установка

```bash
python3 -m venv venv

source venv/bin/activate

pip install --upgrade pip
pip install redun
```

## 3. Запуск пайплайна

Пайплайн автоматизирует весь цикл обработки: индексацию референса, контроль качества (FastQC), картирование ONT-ридов (`minimap2 -ax map-ont`), конвертацию и сортировку BAM, расчет процента картирования и вызов вариантов (Variant Calling).

Для запуска выполните команду:

```bash
redun run pipeline.py main --ref_path reference.fa --fastq_path SRR11535914.fastq

```

### Структура репозитория с результатами:

* `pipeline.py` — код рабочего пайплайна на фреймворке `redun`.
* `parse_flagstat.py` — bash/python скрипт парсинга результатов `samtools flagstat`.
* `flagstat.txt` — текстовый отчет команды `samtools flagstat`.
* `qc_result.txt` — выведенный результат проверки по критерию >90% (содержит "OK" или "not OK").
* `pipeline_dag.png` — графическая визуализация графа задач (DAG).

## 4. Визуализация пайплайна и анализ

Граф задач (DAG) был автоматически сгенерирован и визуализирован с помощью встроенного веб-интерфейса `redun ui`, который считывает историю запусков из локальной базы данных SQLite.

### Как просмотреть граф:

```bash
redun ui
```

После этого интерфейс доступен в браузере по адресу `http://localhost:8000`.

### Отличия полученного DAG от блок-схемы алгоритма:

1. **Потоки данных против Потоков управления:** Блок-схема алгоритма описывает временную последовательность действий и логические развилки управления (`if/else`, циклы). DAG в `redun` описывает исключительно *зависимости по данным* (dataflow). Шаг не выполнится, пока не созданы файлы-потоки от предыдущих шагов.
2. **Параллелизм:** На графе DAG четко видно, какие задачи не зависят друг от друга (например, `run_fastqc` и картирование `map_reads_ont`) и могут выполняться движком параллельно. В классической блок-схеме параллельное исполнение визуализировать сложнее.
3. **Статичность условий:** Условный переход «> 90% (OK / not OK)» в блок-схеме выглядит как развилка (две стрелки из одного ромба). В DAG это отображается как линейный вычислительный узел (`parse_qc`), который принимает файл на вход и выдает строку-результат на выход, не меняя структуру самого графа при разных запусках.
